First published release. It includes the original app plus the hardening and features from pull request #1.

## What's new
- **Config history.** Every time a switch's running configuration changes, the app keeps an encrypted copy (the newest 50 per switch). The Configuration page has a new **History** view: open any earlier copy, or compare it with the current configuration.
- **Port channels: removing a port now works.** Unticking a member, changing a channel's mode, and **Clear** used to fail with "WrongValue" on Catalyst 1300 switches. Tested on a C1300-24MGP-4X.
- **Faster failure when a switch doesn't answer SNMP.** Asking for health from a switch with the wrong community (or one that filters SNMP) now fails within seconds with a clear message. Before, it took about 9 minutes and then reported "ok".

## Behaviour changes to know about
- **The dashboard only opens on the PC running the app** (it listens on 127.0.0.1). To open it from other PCs again, set `SBS_BIND=0.0.0.0`. There is still no sign-in, so do that only on a network you trust.
- **Saved passwords and communities stay on the server.** The browser no longer receives them; a saved switch's fields show "saved — leave blank to keep".
- **SSH remembers each switch's host key** the first time it connects and refuses a changed key until you confirm it in the app (the keys are stored in `known-hosts.json`).
- **SNMPv1/v2c forms now say plainly** that writes travel unencrypted.
- **Running configurations are now kept on disk**, encrypted with the same key as your saved switches, under `config-history/`.
- **Windows service runs as LocalService** instead of LocalSystem (an account with no rights over the rest of the PC). Not yet tried on a real Windows install; set `SBS_SERVICE_ACCOUNT=LocalSystem` before installing to keep the old account. On Linux, the systemd unit runs as its own `sbs` account.
- **Browser security headers** are sent with every page (they block the dashboard being framed by another site, among other things).

## Under the hood
- The server and the browser code are split into smaller files by feature (`routes/`, `public/src/`). The browser still loads a single `app.js`, now built with `npm run build`.
- GitHub runs the tests (Node 22 and 24) and a dependency audit on every push; Dependabot proposes updates weekly.
- New tests, including a replay of a real C1300-24MGP-4X (scrubbed of addresses, names and credentials).

## Upgrading
1. Stop the app (or the service).
2. Get this version: `git pull` on `main`, or download the source zip below and replace the app's files. Keep your existing `state.enc` and `.state-key` (your saved switches) and `logs/`.
3. Run `npm ci`.
4. **If you run it as a Windows service:** run `uninstall-service.bat`, then `install-service.bat` (as Administrator), so the service picks up the new account. Check it starts.
5. **If you used the dashboard from another PC:** set `SBS_BIND=0.0.0.0` first (see above).
6. Start it and open http://localhost:3000. Your saved switches come back as before.
