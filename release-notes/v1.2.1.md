Fixes the Windows service failing to start when the app sits on the Desktop.

## What's fixed
- **The service no longer dies straight after starting when installed in a user's folder.** Since 1.2.0 the service runs under Windows' low-privilege LocalService account. That account can use the app's own folder but cannot open a user's profile around it (`C:\Users\<name>`, with its Desktop, Documents and Downloads). Node.js stopped before the app could load, and Windows only logged `Child process ... finished with 1`.
- **The installer now checks the folder first.** If the app is anywhere inside `C:\Users`, `install-service.bat` stops before creating anything and tells you to move the folder, for example to `C:\sbs-management-tool`.
- **The installer now checks the service really came up.** After starting it, the installer waits up to 30 seconds for the dashboard to answer. If it doesn't, the installer shows the service's own error log (`daemon\*.err.log`) instead of saying it's running.

## If your service won't start
1. Run `uninstall-service.bat` (as Administrator) in the folder you have now.
2. Move the whole app folder out of `C:\Users`, for example to `C:\sbs-management-tool`. Your saved switches, key, history and logs move with it.
3. Run `install-service.bat` as Administrator from the new folder.

Moving the folder is the whole fix, so this works with 1.2.0 too. Once the service runs, you can install this version from the **Updates** window.

If you'd rather keep the folder where it is, set `SBS_SERVICE_ACCOUNT=LocalSystem` before running `install-service.bat`. The service then runs as LocalSystem, as it did before 1.2.0.
