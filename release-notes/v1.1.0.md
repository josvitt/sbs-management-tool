Routed ports, a quieter PoE alert, and a simpler port channel editor.

## What's new
- **Routed ports ("no switchport").** In a port's **Switchport** tab, the Mode list now has **routed (no switchport)** after access and trunk. Choosing it asks you to confirm and says which VLANs the port will leave. Once the port is routed, an **IPv4** tab appears on the same window, where you set its address (static or DHCP), just like a VLAN's IPv4 tab. Switching a routed port back to access or trunk asks first and removes its address.
- **The Interfaces table shows routed ports**: L3 in the L2/L3 column, "routed" in Mode, and the port's address where its VLANs would be.

## Fixes
- **No more PoE fault alert for devices that don't use PoE.** A port linked to something with its own power (a PC, a server, another switch) can report a PoE "fault". The app used to mark the whole switch critical for it. It no longer does. A PoE fault on a port with nothing linked is still reported.
- **Port channels offer only Static and LACP.** The "off" choice is gone; it did the same as Static. An empty channel starts on Static.
- **Port channel window: Cancel is no longer green**, so it doesn't look like the button that saves.
- **Removing a VLAN's IPv4 address** now shows the same spinner and error message as the other buttons, and waits for the table to update before closing.

## Safety
- The app won't let you make a routed port out of the port it believes carries its own connection to the switch, or turn the port holding the switch's management address back into a switchport. Both show the reason instead.

## Upgrading
1. Stop the app (or the service).
2. `git pull` on `main`, or download the source zip below and replace the app's files. Keep `state.enc`, `.state-key` and `logs/`.
3. Run `npm ci`, then start the app.
