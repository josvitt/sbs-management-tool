The app now reads each switch about ten times faster, and puts less load on the switch while it does.

## Faster collection
- **A full read of a switch takes under 2 seconds instead of about 20.** On the recorded C1300-24MGP-4X it now takes about 140 SNMP requests instead of about 1,200, and the dashboard shows exactly the same data.
- **Only the ports that exist are read.** The switch reports 424 port slots on a 24-port model. Before, the app read every slot for eleven per-port tables, such as port mode, VLANs, 802.1X, port channels and spanning tree, and then threw the empty ones away. It now reads only the ports the switch lists as present. If a switch numbers its ports another way, the app reads that table the old way, so nothing goes missing.
- **A table's columns are read together.** Before, a table with seven columns took seven separate reads. It now takes one.
- **Settings are re-read only when they may have changed.** These are inventory, DNS, RADIUS and TACACS+ servers, static routes, voice OUIs and port-channel slots. They are read again after a config change, a reboot, a change made from this app, a manual **Refresh**, or once an hour.

## Gentler on the switch
- **The 100 requests-per-second limit is now enforced for each switch.** Before, short bursts could go over it, because the first request of every table went out without a pause. Every request now waits its turn, whatever sent it.

## Smoother page
- **The dashboard redraws only when there's new data.** The page checks for new data every 30 seconds, but the switch is read every 5 minutes. When nothing has changed, the panels are left alone. Reachability and the CPU/PoE graph still update.
- **Refresh shows fresh data.** Before, pressing **Refresh** while a background read was running showed the previous data. It now waits for that read to finish.

## Under the hood
- New settings, all optional: `SNMP_MAX_RPS` (requests per second per switch, default 100), `SNMP_BULK_VARBINDS` (values per request when columns are read together, default 40) and `SETTINGS_MAX_AGE_MS` (how often settings are re-read anyway, default one hour).
- New offline tests cover each change. The replay of the recorded switch now checks every table against what v1.4.2 produced.
