Changes are safer to make: the switch is no longer read in the middle of a change, a port change that fails part-way is put back, and adding a static route works.

## Safer changes
- **Background reads wait while you change a switch.** When you save a change, the server holds that switch's scheduled 5-minute read and the extra reads that traps start until the change and a short settle time are over. A read that is already running finishes first. This firmware has crashed when a full read overlapped a config change. Before, only your browser paused, and the server's own reads did not.
- **A port change that fails part-way is undone.** When the switch refuses one step of a switchport change (mode, access VLAN, trunk VLANs, or routed and back), the app stops there and puts the port back the way it was, including its IPv4 address. The message tells you either "the port was put back as it was" or "putting the port back failed too, check this port". Before, the next steps were still sent, and a port could be left routed with no address.

## Fixed
- **Adding a static route works.** The IPv4 Addressing panel sent a route type the switch refuses, so every new static route failed. The route table also now names route types correctly: reject, local and remote.

## Tested on a real switch
On 25 November, these changes were made on port gi1/0/4 of a test C1300 through the app's own code, then checked and put back. The configuration was never saved. All 31 checks passed:
- Routed mode ("no switchport") and back to an access port.
- Adding and removing a static address, turning the DHCP client on and off, and adding and deleting a static route.
- Adding and deleting a nameserver, a search domain and a host mapping.
- Two refused steps, refused on purpose, each undone correctly.

## Measured switch load
Two switches were recorded, read only, for the offline tests. These are measured counts, where the v1.6.0 notes gave estimates:
- **SNMP configuration, Flash files and Packet capture together:** 33 requests on the C1300-24MGP-4X and 29 on the C1300X, under a second either way.
- **The full 5-minute read:** 165 requests in 3.4 seconds on the C1300-24MGP-4X. It took 1,017 requests and 26 seconds on the C1300X, which lists more than 400 bridge ports.

## Behind the scenes
- New offline tests cover the port, VLAN, port-channel, IPv4, DNS, AAA and syslog setup writes, using the SETs the switch accepted.
- The offline tests now replay both recorded switches, including the ACL, route table, SNMP configuration, capture and flash panels. Addresses, MACs, names and communities were removed from the recordings.
